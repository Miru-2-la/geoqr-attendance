One scan, five checks, five possible outcomes

When a student scans an event QR code, the backend validates it step by step and stops at the first check that fails. Pick an outcome to replay the exact path.

Outcome to replay

The service runs its checks in this order:
  1. Event exists
  2. Student has not marked yet
  3. Distance within radius (Haversine)
  4. Device not used by another student
  5. Save as PRESENT
